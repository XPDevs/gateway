Gateway

How Search works

Gateway combines a bundled local index with optional, sourced open-data discovery. It runs without a Gateway backend and does not use generative AI.

Local index

Gateway ships with a local index of real, verified websites. It is loaded directly into your browser and stored in IndexedDB. Local matching and ranking do not require a request; the current bundled index contains 50,619 websites, each on its own domain, and every one was contacted over HTTP when the index was built to confirm the site answers. A second, small file, index/xpdevs.json, adds 71 ordinary project pages and is merged into the same searchable corpus at load time.

Live discovery

For a search, Gateway can ask Wikipedia's public API for matching article extracts and current external links. Wikidata provides structured claims such as release dates, founders, headquarters, and official websites. These requests disclose the searched subject to the public API provider; no full history is sent.

Quick Wiki

Quick Wiki is deterministic, not generative. Gateway recognizes common question patterns, matches a Wikipedia article, reads a relevant Wikidata claim when one exists, and formats the value with its property identifier. If structured data is unavailable, it displays a direct extract and labels that fallback clearly.

Ranking

Every result is scored with one hybrid function, so bundled pages, the XPDevs project index, live Wikipedia articles, official sites and cited web links compete on identical terms. Every quantity is defined relative to the corpus actually loaded, so the same code ranks a small custom upload and the full index.

BM25F → × coordination → × phrase bonus → relevance = adjusted / (adjusted + 2)
final = relevance × (0.78 + 0.22 × authority / 10)

  • Field-aware BM25F: title and description are scored as separate fields with k1 = 1.2, title weight 3.0, description weight 1.0, and field lengths normalised with b = 0.55 for titles and b = 0.75 for descriptions, so a title match outranks the same word buried in a long description
  • Corpus-normalised term weighting: idf(q) = ln(1 + (N - n(q) + 0.5) / (n(q) + 0.5)) and w(q) = min(idf(q) / R, 1) ^ 1.35, where N is the size of the active index, n(q) the number of documents containing the term, and R = ln(1 + 1000000) a fixed reference rarity of one document in a million. Because R is a constant, a term's weight depends on its relative document frequency and not on how big the index is: a 60 page upload and a 150,000 page index use identical maths. A term present in every document ends up with no influence at all. window.GATEWAY_RANK_CORPUS can enlarge N to simulate a bigger corpus
  • Coordination: the BM25F score is multiplied by 0.35 + 0.65 × coverage, where coverage is the weighted share of the query a document matched, so one common word cannot outrank a full match
  • Exact phrases: a multi-word query that appears as an exact contiguous run gets 1.35× in the title or 1.12× in the description, with stopwords kept so university of oxford matches that title
  • Bounded relevance: adjusted / (adjusted + 2) saturates into [0, 1), so no term frequency or index size can blow up a score and local results stay comparable with live ones
  • Authority: a pre-calculated static score from 0.0 to 10.0 per domain (reference works, government and academic sites, primary documentation), applied as the multiplier 0.78 + 0.22 × authority / 10. It reorders close matches and breaks ties, and cannot overturn a clearly better one
  • Deduplication: tracking parameters are removed and equivalent URLs are shown once

Matching is whole-token rather than substring, and common words are removed from the query before scoring. Only the documents a query term actually occurs in are scored, through a postings map built when the index loads, and only the best 120 candidates are turned into results, so search cost does not grow with how many pages happen to match.

Query operators

Operators are applied before scoring to the local index and to live sources alike, and are removed from the query so none of them is ever treated as a keyword.

  • site:bbc.co.uk news keeps results on bbc.co.uk and its subdomains
  • site:bbc.co.uk/news news also restricts to that path prefix
  • site:https://www.example.com accepts a pasted URL
  • Several operators are ORed: site:example.com site:example.org report
  • news -site:example.com removes a host and its subdomains
  • apple -fruit removes documents containing that word, on whole tokens only
  • "university of oxford" requires those words adjacent and in order, while still scoring them normally

Typing site: in the search box completes host names from the index itself, and matched query words are marked in result titles and snippets.

Safety & Filtering

Every result passes through a safety layer before it reaches you:

  • Domain blocklist: 25+ dangerous domains are removed (malware, phishing, shock sites, Tor gateways, URL shorteners)
  • Keyword filter: results containing dangerous keywords (malware, crack, warez, etc.) are blocked
  • Tracking removal: query parameters like utm_*, fbclid, ref are stripped from all result URLs

Custom index

You can upload your own JSON index via Settings -> Upload Index. The uploaded index replaces the built-in one and persists across page reloads in IndexedDB, allowing you to customise Gateway with your own data.

For a bounded, dependency-free crawl of public pages, use npm run build:web-index. It reads seeds.txt, follows links to the configured depth, respects robots.txt by default, and writes a merged JSON index without an AI model or search API.

Dark Mode

Dark mode is stored in localStorage and applied before the page renders, so there is no white flash. The toggle works instantly and persists across sessions.

Performance

Gateway is designed to be fast without a Gateway server:

  • Local matching and ranking happen in your browser
  • Public discovery requests are short-lived and independent of the bundled index
  • Search results and API responses are cached for ten minutes for repeat searches
  • IndexedDB persists the index across sessions without re-downloading unchanged data

Open Source

Gateway is built by XPDevs. The full source is available on GitHub. You can inspect, fork, or self-host it.
